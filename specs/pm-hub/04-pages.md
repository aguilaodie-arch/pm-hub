# 页面与交互规约

> 全部为 PC Web。视觉细节（间距、颜色、密度）不做规定，追求朴素可用即可；本文件只管结构、行为、数据。
> 鉴权总规则：除"免登直链 /p/{prototypeId}/"外，全部页面与 API 需登录；未登录访问一律跳转 #/pc/login。
> 全局外观（D32）：深色 / 浅色双主题，侧边栏底部用户区有切换按钮（月亮/太阳图标），选择经 localStorage 记忆，默认深色；登录页固定深色不切换。

## 页面：需求池（#/pc/pool）

### 区块结构
1. 筛选区：关键词（编号/标题模糊）、项目下拉、版本下拉（联动项目：选了项目=该项目版本，未选=全部项目的版本；选项只显示 sprint 名不带项目前缀，D24 2026-10-13 定稿）、状态下拉（六态+全部）、PM 下拉、查询按钮、「导出」按钮（D31：按当前筛选条件导出全部匹配结果为 xlsx，导出列=需求全字段+创建/更新时间，登录即可含研发只读）（优先级筛选已于 D24 移除，字段保留）
2. 操作区：「新建需求」按钮（仅 PM/主账号可见）
3. 列表区：创建时间倒序（D24：created_at desc，编辑不改变行序）；行内可编辑字段 + 操作（详情与预设/共享文件/删除）；分页（D27：每页 20 条，页码栏含总数/上一页/下一页/页码省略，筛选变更回第 1 页）
4. 空态："暂无需求"

### 数据绑定
- 列表行 ← requirement；项目名 ← project.name；版本名 ← version.name（versionId 为 null 显示"—"）；PM 名 ← account.name

## 页面：需求详情（#/pc/req?id={id}）

### 区块结构
1. 字段区：requirement 全部字段，PM 可编辑保存；研发只读。已上线=全只读（A4）
2. 材料区：材料列表（文件名/大小/上传人/时间/下载/删除）+ 上传按钮（研发可见可下载，不可上传删除）
3. 预设计对话区（研发不渲染；D14 单对话体验）：聊天窗 + 「导出 .md」/「下载产物 .zip」/「新对话」图标按钮；进入即展开最新对话，无对话时首条消息自动建会话，「新对话」用于上下文重置（历史会话保留在数据层）；技能不设按钮条，由 Agent 按已安装技能目录自主调用（D15）；技能交付物以 ```file: 围栏产出并渲染为可下载文件卡片（D16）
4. 主账号专属：已上线需求的「回退到研发中」按钮

### 数据绑定
- 字段区 ← requirement + 关联名；材料列表 ← material（按 requirementId）；对话 ← conversation + message

## 页面：原型问答页（#/pc/proto-view?id={prototypeId}[&q={qaLogId}]）

### 区块结构
1. 顶部条：「← 返回」按钮（直接关闭本页回 #/pc/projects，history.replace 语义，D18）+ 原型名 + 「复制直链」按钮
2. 左区：iframe 加载该原型静态页
3. 右区问答侧栏：升级卡（仅 URL 带 q 参数时置顶展示，见下）+ 本次会话问答列表 + 输入框 + 发送按钮
   - 单发式问答（D22）：进入页面不加载历史问答，每次提问相互独立；qaLog 照常落库
   - 升级卡：展示提问人/研发的问题/AI 的回答/AC 式摘要/钉钉推送结果；PM 或主账号且未处理时显示「标记已处理」按钮

### 操作规约
| 操作 | 行为 | 校验 | 反馈 | 异常文案 |
|---|---|---|---|---|
| 提问 | 组上下文（该原型全部 html 抽取的纯文本+本版本需求+知识库检索若 agent2.use_kb=true）→调 LLM→写入 qaLog | 已登录（任何角色）；内容非空 | 回答上屏，下方出现「未解决 · 找产品经理」按钮 | 网关未配置/失败：同需求详情页文案 |
| 未解决 · 找产品经理（D22） | LLM 按 escalate.ac_template 生成 AC 式摘要写 qaLog.summary，feedback→未解决；再向原型上传人的钉钉 userid 发工作通知（标题=原型名，正文=AC 摘要全文+跳转链接 `#/pc/proto-view?id={pid}&q={qaId}`，链接前缀取 dingtalk.hub_base_url），结果写 pushStatus/pushError | 已登录；该问答未升级过；AI 网关可用 | 按钮变"已转交"禁用态；推送成功 toast"已转交产品经理（{姓名}），钉钉已推送" | 重复升级："该问题已转交产品经理"；摘要生成失败："摘要生成失败（模型调用异常），请稍后重试"；推送失败不阻断：toast 提示失败原因，pushStatus=推送失败 |
| 标记已处理（D22） | 写 qaLog.handledBy/handledAt | PM 或主账号；feedback=未解决 且未处理过 | 升级卡状态变"已处理"，按钮消失 | 非待处理："该问答不是待处理状态"；无权限："无操作权限" |

> 免登直链 /p/{prototypeId}/ 为纯静态服务，**不做**任何注入，没有问答入口（反直觉约定见 00 术语表）。
> 问答详情接口权限：提问者本人或 PM/主账号可查看（研发点开他人升级链接返回 403"无查看权限"）。

## 外部集成契约（实现者严格按此边界，禁止越界自建）

### 与开源 RAG 产品（默认 MaxKB，A13）
- D1 已改为内置实现（Chroma + 本地 ONNX embedding），不再对接外部 RAG 产品；D19 起写入口径升级为需求级知识条目+版本级索引。以下契约仅作历史背景保留
- 本系统只做三件事：①归档时把知识条目切块写入内置向量库（旧口径：调 RAG API 写入 version.summary 一篇文档，回存 kbDocId）；②Agent-1/Agent-2 需要知识库上下文时检索片段（带「《标题》（编号）」来源标签）拼入提示词；③#/pc/kb 页提供知识浏览+知识问答（旧口径：iframe 嵌入 RAG 对话页）
- RAG 侧自管：embedding 模型（接内网 Ollama bge-m3）、chunk 策略、topK、召回阈值——全部在其自带管理界面配置，本系统不做对应配置页（反直觉约定⑤）
- RAG API 具体端点在实现期以所选产品官方文档为准，记入 decisions.md

### 与 LLM 网关
- 本系统全部 LLM 调用（Agent-1/Agent-2/归档条目与版本索引生成）统一读 config 的 llm.* 三项；禁止在代码中硬编码任何模型地址或密钥
- 调用失败统一文案见各页"异常文案"列；不重试超过 1 次

### 与静态文件服务
- 原型与材料落盘于数据目录（环境变量 DATA_DIR）；/p/{prototypeId}/ 由静态服务直接映射 prototype.dirPath，免鉴权；材料下载走鉴权 API，不做免登直链

### 与 Jira（D23）
- 单向集成：本系统只做两件事——①「转 Jira」时 POST /rest/api/2/issue 在 jira.project_key 下创建 Story（summary=需求标题，description=LLM 按模板生成的用户故事，issuetype=Story）并回写 issueKey；②需求删除时 POST /issue/{key}/transitions 把 Story 流转到完成类状态（完成/Done/Closed/已废弃等取首个可用）并 POST /issue/{key}/comment 追加"需求池侧已删除"说明
- 永久禁止调 Jira 删除接口；禁止回读/回写 Jira 侧状态与字段（一期不做双向同步）
- 认证统一走 config 的 jira.*（basic：email+api_token）；失败不阻塞本系统任何业务动作，只落 jiraSync=同步失败+jiraError
