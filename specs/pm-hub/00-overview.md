# PM Hub（产品需求工作台）Spec 总览

## 背景与目标

示例公司产品部内部工具。此前用 Axure 做原型、蓝湖托管预览链接，原型数量超出蓝湖免费额度需付费；需求池用 WPS 多维表格维护了三四年，字段臃肿（30 个字段大量僵尸）、与原型和知识完全脱节。本产品一次性替代两者，并把"需求录入 → AI 预设计冷启动 → 原型托管与问答 → 版本归档沉淀知识库 → 知识反哺下一轮预设计"的闭环跑通，让历史知识形成飞轮。内网部署，供产品部 8 名 PM 与 20+ 研发使用；由一名 PM 业余时间以 vibe coding 方式构建和维护，因此**可维护性极简是架构第一原则**：能整体搬来的开源件绝不自建。

## 范围

- 做：
  - 用户中心（账号+三种角色：主账号/PM/研发）
  - 需求池管理（14 字段模型，关联项目与版本，六态状态机）
  - 需求材料区（需求维度附件，共享可见，供 AI 预设计引用）
  - 需求预设计 Agent（下称 Agent-1）：需求维度共享 AI 对话，挂知识库与材料，产出可导出 .md
  - 项目/版本/原型三级管理：Axure 导出 HTML 整目录上传（非 zip）、同名覆盖、免登预览直链
  - 原型问答 Agent（下称 Agent-2）：基于当前原型内容+知识库回答研发提问；单发式问答（D22），研发可点「未解决 · 找产品经理」升级为 AC 式摘要并钉钉推送原型上传人
  - 版本归档（D19）：后台任务逐需求生成结构化知识条目（知识卡），并汇总版本级索引；写入知识库；版本下需求联动标记"已上线"
  - 知识库页（D19）：「知识浏览」（版本→条目浏览/搜索/查看，PM 与主账号可编辑/重新生成）+「知识问答」（基于条目的 RAG 问答）
  - 统计分析（简版：项目/状态/PM 三维度计数 + PM 工作量表）
  - Jira 联动（D23）：需求详情页手动「转 Jira」——AI 按模板生成用户故事并写入 Jira（全局单一目标项目），issueKey 回写建立关联；需求删除时 Jira 侧故事联动废弃（流转完成态+评论，禁止真删除 issue）；失败落"同步失败"状态可重试
  - 配置中心（主账号）：LLM 网关、Agent 提示词、归档摘要模板、钉钉推送、Jira、账号管理、磁盘用量
- 不做（显式排除，防止范围蔓延）：
  - 原型版本历史与更新日志（同名即覆盖，有意为之）
  - 状态自动流转（除"归档联动已上线"外，状态全部人工维护）
  - WPS 历史需求迁移（历史已上线需求留在 WPS 作只读档案；切换日手工补录在途需求）
  - 自建 RAG 引擎、自建 embedding、自建检索配置页（全部用开源 RAG 产品自带能力）
  - 深度统计分析（趋势图、工时分析、自定义报表）
  - 材料进知识库（知识库唯一入口=归档）
  - 视频类附件
  - SSO/钉钉扫码登录、复杂权限矩阵、审计日志
  - Jira 双向同步（Jira 侧状态/字段变更不回传，一期只单向）、批量转 Jira、Epic/版本层级映射、Jira issue 真删除（永久禁止）（D23）
  - 移动端适配（纯 PC Web）
  - 公网访问（仅内网）

## 角色与端

| 角色 | 端 | 在本产品中做什么 |
|---|---|---|
| 主账号（admin，1 个） | PC | 全部 PM 权限 + 配置中心（LLM 网关/Agent 提示词/摘要模板/账号管理/磁盘用量）+ 已上线需求状态回退 |
| PM（pm，8 个） | PC | 建/编/删需求、传材料、预设计对话、建项目与版本、传/更新/删原型、执行归档、处理未解问题 |
| 研发（dev，20+） | PC | 只读看需求池与需求详情（不含预设计对话）、看原型、原型问答（Agent-2）、知识问答、问答「未解决」升级 |

## 技术拓扑（已定决策，实现者不得变更）

- 单体 Web 应用（前后端同仓库）+ SQLite（备份=拷文件）+ 文件系统目录存原型与材料
- 开源 RAG 产品独立 Docker 部署，本系统经 API 与其通信（写入归档摘要、检索知识片段）；知识问答页 iframe 嵌入其对话页
- Embedding 本地化：内网服务器跑 Ollama（默认模型 bge-m3），RAG 产品接 Ollama；embedding 数据不出域
- 全部 LLM 调用走配置中心的网关配置（base_url / api_key / model 三项可配），MVP 阶段填公网 API，成熟后改填合作方 API，只改配置不动代码
- 整体 docker-compose 部署于内网服务器
